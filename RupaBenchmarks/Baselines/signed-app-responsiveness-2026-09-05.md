- Host: Mac16,6, macOS 27.0 (26A5388g), 36 GiB physical memory.
- Product budgets: 60 Hz / 8 GiB reference, as defined by
  [RupaRendering](../../RupaKit/Sources/RupaRendering/DESIGN.md#performance-acceptance).
- Toolchain: Swift 6.4 development snapshot 2026-08-14, compiler `424cae54c1a10da`.
- Outer source: `6d48d4a6`; nested Swift-CAD: `db8b801a`.
- Fixture: 12 authored-mesh cylinders, 6,284 segments each; 150,840 vertices,
  301,632 faces, 44,667,425 package bytes. No CAD features.
- Fixture digest: `fbd691c6eaddf8436279207babc3d729f12336aefa6291c84e047a5c03c3f773`.
  The Debug fixture writer wrote and reloaded this package. This digest is not
  interchangeable with a fixture generated by the Release benchmark binary.
- Only the independent fixture was opened. No user project was changed or saved.

## Reproduced input failure and correction

The initial signed binary (`7d1fe280ebfb2c01aef146f9429ac5b9f2a2fb28b31dd3f461de3fb71e9d278f`)
rendered curved shading, end caps, depth, and matching blue object selection.
However, a 90-second Time Profiler trace recorded 21 main-thread potential hangs,
with a maximum duration of 2.095 seconds.

For the post-load interval, 15.855 seconds of 20.342 seconds of sampled main-thread
running time followed this production mouse-input path:

```text
mouseDown -> refreshSnapOverlayResolution -> SnapResolver
          -> TopologySnapshotService -> DesignDocument.validate
          -> validateAuthoredMeshAuthority -> mesh validation
```

These are inclusive statistical CPU samples, not exact call durations. There
was no CAD topology to return. Commit `4eda99f0` removes this unnecessary request
at its shared demand owner without changing topology validation authority.

Focused regression command, after building the test products:

```sh
scripts/swift-test-timeout.sh 120 -- swift test --skip-build --disable-xctest \
  --filter 'snapResolver|topologySnapshot|topologySummary'
```

Result: 53 tests passed in 11.825 seconds. The new authored-only canary and both
topology-measurement failure canaries ran; existing generated CAD snap and
measurement cases also passed. The initial combined build/test invocation timed
out, and a direct XCTest invocation discovered no Swift Testing cases; neither
is counted as a pass.

## Final live gate

The immutable-buffer equality correction reuses the existing immutable storage
identity. Identical storage compares equal without element traversal; distinct
storage retains the existing value comparison. No cache, storage owner, or
hit-testing change is introduced.

The focused regression failed against the pre-correction test product: the
shared-buffer comparison executed three element comparisons instead of zero.
The same run passed the other 16 GeometryBuffer tests. Test-launch failures and
timeouts before that behavioral result are not counted as regression evidence.

For the correction committed as `6d48d4a6`, a separate
`swift build --build-tests --jobs 2`
completed in 59.09 seconds. The same focused command with `--filter
'geometryBuffer'` passed all 17 tests in 0.209 seconds, including zero element
comparisons for shared storage, value equality for distinct storage, changed
values comparing unequal, builder isolation, and concurrent immutable reads.

The corrected Release build succeeded. Its binary SHA-256 is
`a41810045ccc75754955b95648144dc84eef1178b7a813f6b22ff64103c4841e`,
UUID `C3129E21-3FED-31EE-8655-54C0E4DEDD7A`; strict deep signature verification
passed. The Mac locked again before replacement, so this binary has not yet
been installed or measured. The old test fixture remains clean in the running
application. Pending the same-input signed-App recording; the earlier hangs
keep signed-App input acceptance open until the corrected binary is measured.

The build command exited 0, but its log contains a SwiftCompile diagnostic
reporting exit code 0 as a failure and 189 debug-information verification
warnings. This is not a clean release-build claim; signed live behavior remains
the acceptance evidence required here.
